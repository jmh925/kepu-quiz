# 部署与答辩演示说明

> 面向答辩现场：从零开始到演示结束的每一步，以及评委可能追问的问题与回答口径。

## 一、演示前的准备（建议提前一天做完）

| 步骤 | 命令 / 操作 | 预期结果 |
| --- | --- | --- |
| 1. 重置数据库 | 在 `backend` 目录执行 `python ..\tools\reset_db.py --demo` | 建好 10 张表、创建默认管理员、灌入演示数据 |
| 2. 启动服务端 | 双击 `scripts\run_server.cmd` | 控制台打印数据库路径与大模型状态 |
| 3. 自检接口 | 另开窗口执行 `scripts\run_smoke_test.cmd` | 生成 `backend/tests/smoke_report.md`，49 条用例全部通过 |
| 4. 打开接口文档 | 浏览器访问 `http://127.0.0.1:8000/docs` | Swagger UI 可展开每个接口试调 |
| 5. 打开管理端 | 浏览器访问 `http://127.0.0.1:8000/admin/` | 默认账号 `admin` / 口令 `kepu@2026` |
| 6. 打开网页版学生端 | 浏览器访问 `http://127.0.0.1:8000/app/` | 未登录时入口页有三个页签：学生登录、学生注册、管理员 |
| 7. 导入小程序 | 微信开发者工具导入 `frontend` 目录 | 勾选「不校验合法域名…」后编译成功 |
| 8. 注册一个学生账号 | 在 `/app/` 的「学生注册」页签填登录名与口令 | 登录名 3~20 位字母数字下划线，口令 6~32 位 |

**降级演示最重要的一点**：整个演示**不需要配置 DeepSeek 密钥**。没有密钥时系统自动走内置
题库（150 题 / 6 大主题，每主题 25 题），出题、判题、复盘、错题重练全部可用。答辩时可以说：
「现场没有配置付费密钥，系统自动降级到内置题库，这正是本系统可靠性设计的体现。」

## 二、现场演示脚本（约 8—10 分钟）

### 第 1 幕：学生端主流程（4 分钟）

1. 打开小程序首页 → 选学段「小学高年级」→ 输入「太阳系」→ 点「开始出题」。
   - **讲解点**：等待期间 mascot 台词分档变化（0—8 秒 / 8—20 秒 / 20 秒以上），
     下方轮播科普小知识，把等待时间变成学习时间；提供取消入口。
2. 进入答题页 → 故意答错一题、答对一题。
   - **讲解点**：答错用暖橙而不是纯红，符合面向儿童的情感化设计；
     选错后立即本地判分并给出解析，不需要等服务器。
3. 连续答错 2 题 → mascot 切换到「鼓励」状态并提示「要不要先看看解析？」
   - **讲解点**：不逼孩子一直错下去，这是文案规范里的硬约束。
4. 答完 → 进入复盘报告页。
   - **讲解点**：掌握度进度条 + 三句话总结 + 下一步建议；
     页面明确标注报告来源（「由 AI 生成」或「本次由学习助手生成」），不谎称来源。
5. 打开错题本 → 点「只练错题」。
   - **讲解点**：这条链路**不调用大模型**，毫秒级返回，是大模型不可用时的兜底复习方案。

### 第 2 幕：知识库与检索增强（2 分钟）

1. 进入知识库页 → 上传一份 txt 讲义（可现场新建一个「恐龙小知识.txt」）。
2. 列表出现该文档 → 点「用它出题」。
   - **讲解点**：出题时先用中文 2-gram 词频向量做余弦相似度检索，
     取 Top-3 片段注入 Prompt，让题目**只依据这份资料**，缓解大模型知识陈旧与幻觉问题。

### 第 3 幕：管理端（2 分钟）

1. 登录 `http://127.0.0.1:8000/admin/`。
2. 运行看板：用户数、闯关次数、平均正确率、错题总量、出题来源分布、近 7 天趋势。
3. 题库资源池：新增一道题 → 回到小程序出题，验证**资源池题目被优先命中**。
4. 用户管理：列表显示登录名（没有登录名的显示「游客」），搜索框可按登录名或昵称搜；
   点某个学生的「答题详情」，弹出宽弹窗，四块内容是逐次闯关记录、薄弱知识点排行、
   错题明细与知识库资料。
   - **讲解点**：这条链路一次请求就把一个学生的资料、统计与逐次记录取回来，
     老师能看到孩子具体卡在哪个知识点，而不是只知道错了几道题。
5. 操作日志：展示刚才的增删改都留下了记录。
   - **讲解点**：管理端不是「设计范围」，而是已实现并跑通的功能。

### 第 4 幕：网页版学生端与账号流程（2 分钟）

1. 浏览器打开 `http://127.0.0.1:8000/app/`，页面停在入口页，有三个页签：学生登录、学生注册、管理员。
2. 点「先逛逛（游客体验）」→ 直接出题、答题、看复盘。
   - **讲解点**：不注册也能完整体验，降低第一次使用的门槛。
3. 回到入口页，用「学生注册」建一个账号（登录名 + 口令），然后重新走一次闯关。
   - **讲解点**：注册后系统会把游客期间的闯关记录、错题本与经验值并到正式账号上
     （错题按「用户 + 题干」唯一索引去重、错误次数累加），不会让先试的孩子白玩。
4. 在「管理员」页签用管理员账号登录。
   - **讲解点**：登录成功后直接跳 `/admin/`，不需要手敲后台地址。
5. 口头补充：网页版是零构建的原生 HTML/CSS/JS，没有构建步骤、没有第三方依赖，
   和小程序共用同一套后端接口；小程序端仍走微信登录入口。

### 第 5 幕：可靠性与测试（2 分钟）

1. 打开 `backend/tests/smoke_report.md`。
   - **讲解点**：40 条功能用例 + 7 条性能用例 + 9 条降级用例，全部通过，数据由脚本实测生成。
2. 打开 `tools/acceptance.py` 的运行输出。
   - **讲解点**：8 组检查一把跑完——后端冒烟、管理端接口联通性、前端静态检查、错题本 CRUD、
     题库完整性与学段分离、学段分级出题、论文成稿检查、网页版端到端；另纳入学生账号与错题收录、
     管理端答题详情分类面板两组。网页版端到端用的是真实浏览器，跑完会留下截图。
3. 口头说明三层降级：出题 → 内置题库；报告 → 规则模板；复习 → 不依赖大模型。

## 三、常见追问与回答口径

| 评委可能问 | 建议回答 |
| --- | --- |
| 为什么用 SQLite 而不是 MySQL？ | 本系统面向单机演示与中小规模应用，SQLite 零配置、单文件、免运维；表结构与 SQL 语法都按可迁移 MySQL 编写，数据访问层已封装，迁移只需替换连接与方言。 |
| 检索为什么不用向量数据库？ | 单文档规模下分块数量只有几十个，中文 2-gram 词频向量 + 余弦相似度在毫秒级完成，且零额外依赖；引入向量库会显著增加部署复杂度，收益不明显。词频向量的语义匹配能力确实弱于嵌入向量，这一点已写进「研究存在的不足」。 |
| 怎么防止大模型给未成年人出不合适的内容？ | 双向过滤：输入侧做敏感词与长度校验（命中返回 4002）；输出侧逐题过滤，不合规的题目直接丢弃，并用内置题库补齐题量，保证题量与体验都不塌。生产环境建议替换为微信内容安全接口，接口已预留。 |
| 微信登录真的接了吗？ | 没有。小程序端目前是**预留接入点**：`services.login()` 收到 code 时以本地方式生成账号标识，便于不依赖微信后台也能完整演示；接入时只需在服务端补上向微信校验凭证、换取 openid 的那一步，其余逻辑与数据表都无需改动。学生账号本身是可用的——网页版学生端用「登录名 + 口令」注册登录，口令以 PBKDF2-HMAC-SHA256 加每账号随机盐存库。论文第 5 章据实写了这一点。 |
| 学生不注册会白玩吗？ | 不会。游客体验会建一个不带口令的临时账号，注册或登录后调用合并接口，把闯关记录、答题记录、复盘报告、知识库资料与错题全部改归正式账号，经验值累加；错题按「用户 + 题干」唯一索引去重，同题只累加错误次数；合并完成后游客账号置为停用。 |
| 错题本是只增不减吗？ | 不是。答错即入库并累加错误次数，答对视为已掌握、从错题本移除，所以错题本里始终只有还没掌握的内容；「只练错题」就按错误次数从高到低取题重组成练习卷，不调用大模型。 |
| 题目只有单选吗？ | 是。当前题库与大模型 Prompt 都只产出单选题，论文第 7 章已把多题型列为后续工作，没有夸大。 |
| 有没有做学习效果的对照实验？ | 没有做，因此论文没有写任何效果类结论。测试章节只报告了能真实复现的接口功能、性能与降级数据；学习效果验证列为后续工作。 |
| 系统的技术难点在哪？ | 三点：①大模型输出不稳定，需要 JSON 稳健提取 + 两级过滤 + 题库补齐；②出题耗时 10—40 秒，需要把等待过程设计成可感知、可取消、有教育价值的体验；③面向未成年人的内容安全与学段适配，需要把「适合中小学生」落成可校验的参数约束。 |
| 管理端怎么做的鉴权？ | 口令用 PBKDF2-HMAC-SHA256（12 万次迭代 + 每账号随机盐）存储；连续 5 次失败锁定 60 秒；登录后签发 2 小时有效期的 JWT，请求头 `X-Admin-Token` 携带；所有写操作记入 `admin_logs` 便于审计。 |

## 四、上线部署（非答辩必需，供参考）

1. **服务端**：任意支持 Python 3.10+ 的服务器（云主机 / 容器均可）。
   ```bash
   pip install -r backend/requirements.txt
   cd backend && python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
   ```
   生产环境请务必通过环境变量替换 `JWT_SECRET`、`ADMIN_PASSWORD`、`DEEPSEEK_API_KEY`，
   并把 `CORS_ORIGINS` 收敛到实际域名。
2. **反向代理**：用 Nginx 暴露 443 并转发到 8000，配置 HTTPS 证书。
3. **小程序**：把 `frontend/config.js` 的 `IS_DEV` 改为 `false`、
   `BASE_URL` 改为已备案的 https 域名；在小程序后台配置 request 合法域名。
4. **数据备份**：SQLite 单文件，直接备份 `backend/data/kepu.db` 即可。
