# 第1章 绪 论

## 1.1 研究背景与意义

### 1.1.1 研究背景

2021年，中共中央办公厅、国务院办公厅印发《全民科学素质行动规划纲要（2021—2035年）》，把青少年科学素质提升列为重点任务，提出要激发青少年的好奇心和想象力，增强科学兴趣、创新意识和创新能力。2022年，教育部印发《义务教育课程方案和课程标准（2022年版）》，将科学素养纳入培养目标，小学阶段的科学课程从一年级起开设。政策层面的指向是明确的，但政策落到学生的日常学习上，还存在明显的空档。

空档首先来自课时。小学阶段的科学课每周课时有限，课堂上教师需要完成规定的教学进度，很难留出让学生反复提问、自由探索的时间。课外科普资源的供给也不均衡。城市学生可以去科技馆、自然博物馆，但参观受开放时间与家长时间的双重限制；农村和县城的学生这类机会更少。科普读物是另一种常见形式，但读物的内容组织是线性的，学生读完不容易知道自己掌握了多少，也不容易发现自己的知识盲区。换句话说，政策提出了培养科学兴趣的目标，而学生日常可用的、能反复练习并且能给出反馈的科普载体并不多。

其次，现有的科普类应用没有很好地补上这个空档。从国内已有的研究看，面向青少年的科普类小程序数量偏少，内容组织多为单向浏览，用户看完即走；已有的教育类小程序则普遍存在三个问题：错题处理停留在“记录”层面，缺少诊断与归因；题目依靠固定规则随机生成，无法随学生水平调整；激励设计容易走向两个极端，要么过于单调，要么喧宾夺主。这些问题在答题类产品中同样存在——学生做完一轮只知道对了几道题，既不清楚错在哪里，也看不出下次该练什么。

技术条件方面，最近几年出现了两点变化，使这类应用的实现难度明显下降。一是微信小程序这类免安装的轻量应用形态已经普及，学生和家长不需要下载安装包，在自己的手机上就能打开，入口浅、使用成本低，适合作为低龄段的载体。二是大语言模型的出题能力可以按学生说出的主题现场生成题目，绕开了固定题库很快被刷完的问题。到2025年前后，国内大模型在推理能力上有所提升，调用成本明显下降，使这类应用在普通设备上具备可行性。但模型的输出并不稳定：题目的字段结构可能不合规，难度可能与学段不符，内容也可能不适合未成年人，如果直接下发给学生，既可能误导学习，也存在内容安全的隐患。

综合来看，目前缺少的是一个面向中小学生、按学段分级、能把“出题—答题—讲解—错题沉淀—长期激励”连成闭环的答题系统。它需要既能借助大模型解决题库固定的问题，又能在模型不可用时依靠自身题库继续工作；既能让低年级学生独立操作，又能让教师和家长看到具体的学习情况。本课题正是针对这个缺口展开的。

### 1.1.2 研究意义

本课题的理论意义，在于把两个通常停留在提法层面的问题落成可以验证的约束。

其一是学段适配。关于“因材施教”“分层教学”的讨论很多，但在系统实现层面，学段适配往往被简化为“题量多少不同”。本课题进一步把学段适配落实为一组具体参数：不同学段的题量、题干长度上限、选项长度上限，并要求题库本身按学段分开存放，使同一道题不会既出现在小学低年级又出现在初中。这些约束不是设计上的口号，而是可以被检查脚本逐条核对的规则，这就把“适配”从主观判断变成了客观条件。

其二是大模型不可用时的可用性。把大模型引入教育类应用的研究不少，但多数讨论集中在效果层面，对“模型调用失败或未配置时系统怎么办”讨论不多。本课题设计了三层降级链路：出题环节降级到内置题库，复盘报告环节降级到规则模板，只练错题环节完全不调用模型。这条链路保证系统在没有API密钥或断网的情况下仍能走通全部流程，也为同类应用提供了一个可复现的实现思路。

本课题的实践意义体现在三个方面。第一，对教师和家长而言，系统提供了可查看的学情记录。管理端可以按学生查看逐次闯关记录、薄弱知识点排行、错题明细和同伴对战记录，教师据此能看出学生具体卡在哪个知识点上，而不只是一个正确率数字。第二，对内容维护而言，题库以独立的JSON文件组织，学校或教师可以按自己的教学进度补充题目，不需要改动程序代码，也不需要重新部署；运行数据存放在单个SQLite文件中，备份和迁移就是拷贝一个文件。第三，对部署条件而言，整套系统不依赖付费的云服务或数据库服务，在普通个人电脑上就能运行，对缺乏技术维护力量的中小学来说，这一点比功能数量更实际。

## 1.2 国内外研究现状

### 1.2.1 国内研究现状

国内与本课题相关的研究大致可以分为三条线：教育类小程序的设计与开发、科普类小程序的开发与应用、大语言模型在教育场景中的应用。

教育类小程序的设计与开发研究起步较早，成果集中在学科练习和教学辅助两个方向。马庆祥梳理了微信小程序在教育领域的应用形式；此后，孙磊等人讨论了微信小程序在“互联网+教育”中的作用与建设路径；涂启泮研究了小程序在实践教学环节的使用方式。在具体实现层面，毛凌志、史桂红、韦彩仁等人分别以教育类、回收类、信息管理类小程序为例，讨论了基于uni-app的开发方法，这类研究的共同特点是关注跨端开发与工程实现，对学习效果的分析相对较少。学位论文方面，梁骁研究了基于微信小程序的移动学习平台的建设与应用；吕翠莲开发了作业辅导类小程序并做了教学应用；王磊设计了基于深度学习的小学数学辅助学习系统；丁梓琦则专门讨论了小程序后台管理系统的设计。马轶群针对小学数学运算练习做了小程序的设计与开发研究，与本课题在题型设计上有相近之处。这些研究说明，小程序作为教育类应用的载体在技术上是成熟的，但在学习反馈的深度上还有提升空间。

科普类小程序的研究更贴近本课题的选题。聂鑫雨研究了新媒体背景下科普小程序的开发，其调查发现科普内容的受众以成年人为主，青少年群体被覆盖得不够，而科普场馆的展品又受时间与场地限制，能够触达的学生有限；该研究还发现，中小学生在内容呈现方式上更偏好视频配图文的形式，并且更愿意关注课程标准以外的科学知识。徐金婵基于交互式体验理论开发了校园植物科普小程序，并在生物学教学中做了应用，其研究指出移动应用普遍存在理论指导匮乏、学习资源不足的问题。梁晴雪设计了基于DeepSeek的小学数学口算小程序，在需求分析阶段明确提出口算类产品存在错题处理只记录不诊断、题目无法自适应、激励设计易两极分化三个问题，并在实现中引入了智能诊断归因。这三项研究分别从内容覆盖面、交互体验和反馈深度三个角度指出了现有产品的不足，为本课题的功能取舍提供了直接依据。

大语言模型在教育场景中的应用是近两年国内研究的热点。陆道坤分析了DeepSeek引发的教育领域变化及其应对；陈文智讨论了人工智能对教育形态的影响；王闻萱等人则从技术特征与价值取向的角度分析了国内生成式人工智能的发展路向。总体来看，这类研究多为趋势判断和理念讨论，落到具体系统实现上的成果还不多，尤其是把大模型与小学阶段的答题练习结合起来的研究较少。这既说明方向是新的，也说明在落地上还有工作可做。

### 1.2.2 国外研究现状

国外与本课题相关的研究主要集中在三个方面：游戏化学习的效果验证、移动学习与教育类应用的设计、检索增强生成技术。

游戏化学习的效果在国外得到了较多实证检验，相关研究已经积累到可以汇总比较的规模。Barz等人采用元分析的方法，对学校场景下数字游戏化学习干预的效果进行了汇总，考察的是一系列干预对认知、元认知以及情感动机类学习结果的影响；Tokac等人同样采用元分析，专门整理了游戏化学习与学生数学成绩之间的关系研究。这类汇总研究为在练习环节引入适度的游戏化机制提供了实证依据。不过相关研究也普遍提示，游戏化机制的效果与设计方式密切相关，过度强调竞争与奖励可能反而分散注意力，这一点对本课题的激励机制设计有直接参考价值。

移动学习与教育类应用方面，Calder等人系统讨论了移动技术在数学教学与学习中的使用方式；Outhwaite等人采用内容分析和定性比较分析的方法，考察了教育类数学应用在哪些条件下更能促进学习；Walter等人对小学阶段的数学应用做了横向评测；Nordby等人关注了小学数学课堂中计算思维的培养活动。随着人工智能技术进入课堂，Song等人考察了小学师生对在数学课堂中使用人工智能工具的看法，Kuo等人则开发了一个用于小学数学问题解决的AI学习伙伴，探索了人工智能在学习陪伴场景中的实现方式。这些研究共同说明，教育类应用的效果并不取决于是否使用了新技术，而取决于反馈是否具体、难度是否合适、内容是否与学生的实际水平匹配。

检索增强生成方面，Lewis等人提出了检索增强生成方法，把参数化知识与外部检索结果结合起来，用于知识密集型任务，以缓解模型凭空生成内容的问题。此后，Es等人提出了针对检索增强生成系统的自动化评测框架，从忠实度和答案相关性等维度评价生成质量；Xiao等人针对中文场景构建了通用中文嵌入资源包，为中文检索与语义匹配提供了基础工具。此外，Lee等人研究了基于协同过滤的课程推荐模型，讨论了如何根据历史记录为学生推荐合适的学习内容。这类研究为本课题的知识库检索出题环节提供了思路：与其让模型凭记忆出题，不如先从学生上传的资料中检索出相关片段，再依据片段生成题目，从而把题目的依据限定在可信来源上。

综合国内外研究可以看出三点。第一，小程序和移动应用作为教育载体的技术可行性已经充分验证，相关工程实践也比较成熟。第二，游戏化学习的效果有实证支持，但设计不当会产生副作用，需要控制竞争与奖励的强度。第三，把大模型引入教育应用是新的方向，已有研究多集中在效果与理念层面，对模型输出的结构化约束、学段适配以及调用失败后的降级处理关注不足。本课题要做的，正是在这些方面补上具体的实现工作。

## 1.3 研究内容与方法

### 1.3.1 研究内容

本课题的研究对象是中小学生科普知识闯关系统，使用对象为小学低年级（1—3年级）、小学高年级（4—6年级）和初中（7—9年级）三个学段的学生，同时为教师和家长提供学情查看功能，为管理人员提供题库与用户管理功能。研究边界限定在科普主题与语文、数学、英语三个基础课程主题，不涉及其他学科。

研究内容围绕“出题—答题—讲解—复盘—错题沉淀”这条主线展开，具体包括四个部分。

需求分析部分，通过文献梳理与问卷调查了解学生、教师和家长对科普练习类应用的实际需求，划分功能需求与非功能需求，并从技术、操作与社会三个方面论证可行性。

系统设计部分，确定前后端分离的总体架构与分层结构，设计出题、答题与判题、复盘报告、错题本、知识库、用户与个人中心六个基础功能模块，并在此基础上设计语文、数学、英语基础课程题库、同伴对战和段位成长阶梯三项扩展功能；完成数据库的概念模型与十一张数据表的逻辑结构设计。

系统实现部分，按照设计完成各模块的编码实现，重点解决四个技术问题：一是大模型出题的结构约束与内容过滤，以及题库兜底；二是学段适配参数的落地与题库分级；三是错题在答错、复习、对战等多种路径下的一致性处理；四是异步同伴对战中试卷一致性与对手数据真实性的保证。

测试验证部分，采用功能测试、性能测试和降级异常测试三类方法，覆盖学生端与管理端的全部接口，并引入真实浏览器端到端测试与多视口界面审计，检查静态资源类型、布局溢出、点击目标尺寸与文字对比度等实际可用性问题，最终形成可复现的测试记录。

### 1.3.2 研究方法

本课题采用以下四种研究方法。

文献研究法。查阅国内外关于游戏化学习、移动学习、教育类小程序开发、大语言模型应用与检索增强生成的文献，重点参考梁晴雪、徐金婵、聂鑫雨等人对教育类小程序的调查结论，以及Barz、Tokac等人对游戏化学习效果的元分析结果，明确既有产品在错题诊断、难度自适应与激励机制上的不足，作为本课题功能取舍的依据；技术层面参考检索增强生成的原始文献与FastAPI、小程序开发文档，确定技术路线。

问卷调查法。围绕科普练习的使用现状与功能期望设计问卷，面向中小学生家长和小学教师发放，了解学生当前接触科普知识的途径、家长对现有科普类应用的满意程度、以及对分级出题、错题复习、练习时长控制等具体功能的期望程度，为功能需求的优先级排序提供依据。问卷的设计与统计结果在3.2节说明。

行动研究法。系统实现过程按“做一项功能—写验收脚本—跑出问题—回改—复跑”的循环推进，每完成一个模块就补一段可重复执行的检查脚本，把人工观察变成脚本判定。前期原型开发中据此发现了若干仅靠浏览代码或人工点击难以察觉的问题，例如题库中某道题的解析与标注答案自相矛盾，而界面上显示完全正常。这说明仅凭肉眼验收不足以支撑长期修改，后续工作要延续边做边验的方式，具体的发现与修正过程见5.5节。

个案研究法。选取小学低年级、小学高年级、初中三个学段各一名学生账号作为观察对象，走完注册、答题、复盘、错题复习、对战、段位提升的完整流程，通过管理端查看其答题记录与错题明细，检查系统记录的内容是否与学生的实际操作一致，以此判断功能是否达到预期目的。
