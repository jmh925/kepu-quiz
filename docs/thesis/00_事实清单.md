## 二、技术栈（全文唯一口径，不得出现第二套说法）

| 层次 | 实际选型 | 说明 |
| --- | --- | --- |
| 学生端（小程序） | 微信小程序原生框架（WXML / WXSS / JS / JSON），CommonJS 模块化 | 6 个页面 + 1 个吉祥物组件 |
| 学生端（网页版） | 原生 HTML + CSS + JavaScript（零构建、无第三方依赖），由 FastAPI 以 TypedStaticFiles 托管于 `/app/` | 单页应用；未登录入口页含学生登录、学生注册、管理员三个页签 |
| 管理端 | 原生 HTML + CSS + JavaScript（零构建、零依赖），由 FastAPI 以静态目录托管于 `/admin/` | 5 个功能区 + 单个学生的答题信息分类面板 |
| 后端 | Python 3.13 + FastAPI + Uvicorn + Pydantic v2 | 分层：routers / services / database / llm / question_bank / grades / safety / wrongbook / admin / admin_db |
| 大模型 | DeepSeek（OpenAI 兼容 `/chat/completions`，httpx 调用，模型 deepseek-chat） | 未配置 Key 时自动降级 |
| 降级题库 | 内置科普题库 **150 题** / 6 大主题（天文、地理、生物、物理、化学、科技），每主题 25 题 | 拆为 `backend/app/bank_part_a.json`（天文、地理、生物，75 题）与 `backend/app/bank_part_b.json`（物理、化学、科技，75 题），由 `question_bank.py` 载入；关键词主题匹配 + 随机抽样。旧 60 题已归档到 `docs/repo/legacy_question_bank_60.json`，不参与运行 |
| 检索增强 | 轻量 RAG：文档解析 → 段落+长度分块（约 300 字）→ 中文 2-gram 词频向量 → 余弦相似度 → Top-3 片段注入 Prompt | 未引入向量数据库 |
| 数据库 | SQLite（10 张表，原生 SQL，连接复用 + 线程锁），可平滑迁移 MySQL | 标准库 sqlite3，零依赖 |
| 鉴权 | PyJWT 签发 HS256 Token（学生端 7 天；管理端 2 小时）＋ 管理端固定 Token（便于调试） | 学生端三种入口：登录名 + 口令注册登录、游客体验、小程序 code 登录；游客数据可经 `/user/merge-guest` 并入正式账号 |
| 内容安全 | `safety.py`：输入侧敏感词与长度校验（命中返回 4002）；输出侧逐题过滤并用题库补齐 | 词表为最小可用集合 |
| 学段适配 | 小学低年级（1—3 年级）/ 小学高年级（4—6 年级）/ 初中（7—9 年级）三档 | 影响题量、题干长度、用词难度、报告语气 |

## 五、界面清单

学生端小程序 6 页：`pages/index`（去闯关）、`pages/quiz`（答题闯关）、`pages/report`（复盘报告）、
`pages/wrong`（错题本）、`pages/knowledge`（知识库）、`pages/profile`（我的）；另有吉祥物组件 `components/mascot`。

网页版学生端（源码目录 `web/`，由 FastAPI 托管于 `/app/`）：零构建的原生单页应用，
未登录时入口页提供「学生登录 / 学生注册 / 管理员」三个页签，学生登录与注册走 `/api/v1/user/*`，
管理员页签直接调用 `/api/v1/admin/login`，登录成功后跳转 `/admin/`，无需手工输入地址；
支持游客体验入口，登录后进入与小程序一致的闯关主流程。

管理端 5 个功能区：运行看板、题库资源池、用户管理、闯关记录、操作日志。
用户管理列表显示登录名（无登录名的显示「游客」），搜索框按登录名或昵称检索；
点击「答题详情」打开宽弹窗，把单个学生的数据分为四块展示：
一、逐次闯关记录；二、薄弱知识点排行；三、错题明细；四、知识库资料。

视觉与文案规范：天蓝主色 `#4FC3F7`、胶囊按钮、卡片圆角 24rpx、题干字号 ≥ 36rpx、可点按区域 ≥ 88rpx、
**答错用暖橙 `#FF8A65` 而非纯红**；全篇不出现「错误 / 失败 / 排名」等字眼；
吉祥物「小科」用纯 CSS 绘制，含待机 / 思考中 / 答对 / 差一点点 / 鼓励 / 通关六种状态。

## 八、写作口径与红线

1. **只写实现了的东西**。管理端已实现（不仅是设计）；微信 `jscode2session` 未接入（写成预留）；
   题型只有单选（不得写多选、判断）；数据库是 SQLite（不得写 MySQL）。
2. **数据必须可追溯**：第 6 章只能用第七节的数据；不得编造并发用户数、满意度、学习提升幅度。
3. **图表引用规范**：图名在图下方、表名在表上方，编号按章（图 4-1、表 4-1）。
4. **语言风格**：学术书面语，第三人称，不用「我们」「大家」；不出现「本文首次提出」等夸大表述；
   不出现 Markdown 加粗滥用；段落长度适中，避免口语化。
5. **每章至少 2 节**，节内可再分小节；结论必须编入章节号（第 7 章 结 论）。
6. 参考文献只在需要处用上标序号标注（如 `[1]`），全文统一使用 `[n]` 形式。
7. 涉及「降级」时必须写清楚三层：出题降级到内置题库、报告降级到规则模板、复习（只练错题）不依赖大模型。
8. **账号体系据实写**：学生可用登录名与口令注册登录，也可先用游客身份体验、之后再合并数据；
   小程序仍以微信 `code` 登录为入口，微信服务端校验是**预留**，不得写成已接入。
   错题本语义为「答错入库并累加错误次数、答对视为已掌握并移除」，不得写成只增不减。
   网页版学生端与管理端都是**已交付**的实现，不得写成「设计范围」或「尚未实现」。
